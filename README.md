# MT5 自動売買スケルトン（Python）

MetaTrader5 公式 Python API を使った、差し替え可能な自動売買の骨組み。
現在は**デモ口座での動作確認**を想定しています。戦略ロジックは `strategy.py` に実装するだけで差し替えられます。

## 概要

- 一定間隔でローソク足を取得し、**新しい確定足が発生したときだけ**戦略を評価して発注します。
- 発注は `magic` 番号で管理し、**このボットが発注したポジションのみ**を操作します（手動・他EAのポジションには触れません）。
- 現在は**トレンド／レンジを見分けて切り替える2戦略（EMAクロス／RSI逆張り）**が組み込まれています。

## 前提

- **Windows**（MetaTrader5 パッケージは Windows のみ対応）
- MetaTrader 5 端末がインストール済み
- 取引口座（**デモ推奨**）へログイン済み

## MT5 側の設定

1. MT5 端末を起動し、取引口座（デモ推奨）にログインする。
2. `ツール` → `オプション` → `エキスパートアドバイザー` タブを開く。
3. **「アルゴリズム取引を許可する」** にチェックを入れて `OK`。

### ⚠ 重要: 対象シンボル × 時間足のチャートを開いておく

MT5 の Python API は、**端末がローカルに保持している履歴データ**からレートを取得します。
端末は「あるシンボルのチャートを開いたとき」に、そのシンボル × 時間足のヒストリカルデータをサーバーから同期します。

そのため、**使用する銘柄・時間足のチャートを MT5 上で一度開いて履歴を同期**しておかないと、
`copy_rates_from_pos()` がデータを返さず、ボットが取得に失敗します。

- 例: `config.json` で `"symbols": ["BTCUSD"]`, `"timeframe": "M5"` なら → MT5 で **BTCUSD の 5分足チャートを開く**（候補に追加する銘柄はすべてチャートを開いて履歴を同期）。

履歴が無い場合、後述の「起動時の自己診断」が検知して案内を出します。

## 現在の戦略（トレンド / レンジの2レジーム切替）

確定足ごとに ADX(14) で相場を判定し、**トレンド相場では EMA クロス**、**レンジ相場では RSI 逆張り**へ自動で切り替えます。
いずれも TP/SL（利食い・損切り）を注文時に設定します。

相場判定は `regime_timeframe`（既定 `M15`）の**上位時間足**で行います。つまり「M5 の足で売買シグナルを出しつつ、M15 でトレンドかレンジかを見極める」構成です。シグナル判定（EMAクロス / RSI）・ATR・TP/SL ・エントリーはすべて `timeframe`（M5）のままです。

### 銘柄の選別（単一銘柄ローテーション）

取引対象は `symbols`（ホワイトリスト）の中から、確定足ごとに動的に選びます。

- **フラット時**: 全候補の直近確定足を走査し、戦略が実際にシグナル（BUY/SELL）を出した銘柄を候補に、補助指標（トレンドは ADX 高、レンジは ADX 低）で並べた最上位へエントリー。
- **保有中**: その銘柄だけを評価。他銘柄にシグナルが出ても乗り換えず、**TP/SL の到達を待ちます**。

### 相場判定（regime.py）

`regime_timeframe`（既定 `M15`）の直近確定足の ADX(14) で相場を判定します。

| ADX（14, 上位足） | 判定 | 使用戦略 |
|---|---|---|
| `25.0` 以上 | トレンド | `EMACrossStrategy`（EMA20/75/200 クロス） |
| `25.0` 未満 | レンジ | `RSIRangeStrategy`（RSI 逆張り + ADX フィルタ） |

上位足は「完成した足」だけを使います（形成中の M15 足の途中価格で判定しません）。起動時に `timeframe` と `regime_timeframe` の両方のチャート履歴が取得できることを確認します（無ければスキップ）。

### トレンド相場（EMA20/75/200 クロス）

`strategy.py` の `EMACrossStrategy` が担当します。EMA20 と EMA75 のクロスを売買シグナルに、EMA200 を長期トレンドフィルタに使います。

| 条件 | シグナル | 動作 |
|---|---|---|
| EMA20 が EMA75 を下→上に抜ける（かつ価格 > EMA200） | `BUY` | 買い |
| EMA20 が EMA75 を上→下に抜ける（かつ価格 < EMA200） | `SELL` | 売り |
| トレンドに逆らうクロス（価格が EMA200 の反対側） | `HOLD` | 見送り |
| それ以外 | `HOLD` | 何もしない |

### レンジ相場（RSI 逆張り + ADX フィルタ）

`range_strategy.py` の `RSIRangeStrategy` が担当します。ADX が閾値未満（レンジ）のときだけ発火し、RSI の売られすぎ/買われすぎからの反転を狙います。

| 条件 | シグナル | 動作 |
|---|---|---|
| RSI が売られすぎ(30)を下から上に抜けて反転 | `BUY` | 買い |
| RSI が買われすぎ(70)を上から下に抜けて反転 | `SELL` | 売り |
| ADX が閾値以上（トレンド） | `HOLD` | 見送り |
| それ以外 | `HOLD` | 何もしない |

### ボックスレンジ逆張り戦略（検証中）

`box_strategy.py` の `BoxRangeStrategy` が担当します。レンジ（ボックス）の上限/下限へ指値で逆張りします（`--box` で単一戦略として検証）。仕様は [`SPEC_BOX_STRATEGY.md`](SPEC_BOX_STRATEGY.md) を参照。

| 条件 | シグナル | 動作 |
|---|---|---|
| ADX 低 **かつ** BB 幅狭（レンジ判定）で、安値が Box_Low をタッチ | `BUY` | Box_Low に指値買い |
| 同上で、高値が Box_High をタッチ | `SELL` | Box_High に指値売り |
| ADX 高または BB 幅広（トレンド） | `HOLD` | 見送り |

- **決済**: TP = Box_Mid（中央線）、SL = バンド端 ± `box_sl_buffer_atr`×ATR。エントリー時に固定（追従なし）。
- **指値約定**: バックテストでは「バンド到達で約定、窓開けは open で約定」を再現します（成行の close 約定ではない）。
- Box の計算は `.shift(1)` で見通しバイアスを排除しています。

### 発注時の挙動

- **リスク正規化**: 1 トレードの最大損失が「口座証拠金 × `risk_percent`」になるように、ロットを自動計算します。
- ロットは **SL 距離と 1 ティックあたりの損益（`trade_tick_size` / `trade_tick_value`）から逆算** します。これにより EURUSD と BTCUSD のような価格スケールの異なる銘柄でも、同じリスク額で発注されます（ティック価値が取れない銘柄は `lot` をフォールバックに使用）。
- **テイクプロフィット / ストップロスは ATR 倍数**（例: `ema_sl_atr=2.0` なら「エントリー価格 ± 2×ATR」）で設定します。銘柄のボラティリティに比例するため、BTC でも FX でも同程度の「相場的な動き」で決済されます。
- 逆向きポジションを保有中に逆向きシグナルが出た場合は、決済してから新規（＝ドテン）。
- 同じ向きのポジションを保有中は追加発注しません（増玉なし）。
- **相場が切り替わるとき、旧レジームで建てたポジションは手仕舞わず TP/SL の到達待ち**（新レジームのシグナルでは反転しません）。

> 各しきい値・期間・TP/SL 幅は `config.json` の `ema_*` / `adx_*` / `rsi_*` / `range_*` / `risk_*` / `atr_*` 項目で変更できます。
> TP/SL はブローカーが定める最小ストップ距離（`stops_level`）より十分離す必要があります（近すぎるとリジェクトされます）。ATR の小さい銘柄では ATR 倍数を上げるなどして調整してください。

## バックテスト

過去のローソク足を古い順に1本ずつ戦略へ流し込み、本番と同じ意思決定（レジーム判定 → シグナル → エントリー/ドテン）を再現して、成績を **R（リスク倍数）** で集計します。

R とは「SL 距離の何倍動いたか」（損益価格幅 ÷ SL距離）で、ロットや口座通貨に依存しないため、EURUSD と BTCUSD を同じ物差しで比較できます。勝ちトレードは `+1.0R` など、負けは `-1.0R` などと表記されます。

> **検証の結論（2026-10 時点）**: 本戦略（EMAクロス／RSI逆張り）は、2000年以降に持続的なエッジを持たないことが 55 年分のバックテストで確認されています。概要と経緯は [`BACKTEST_FINDINGS.md`](BACKTEST_FINDINGS.md) を参照してください。バックテスターは「改良で稼げるか」を実弾投入前に見極める道具として使ってください。

### 実行（MT5 から取得）

MT5 端末へログイン済みの状態で:

```powershell
# config.json の全銘柄をバックテスト
.\venv\Scripts\python.exe backtest.py

# 単一銘柄だけ
.\venv\Scripts\python.exe backtest.py --symbol EURUSD
```

出力例:

```
=== EURUSD（実データ 2018-06-01〜2026-10-10） ===
  トレード数: 478   勝率: 45.2%   合計R: -45.11
  平均R(期待値): -0.094   PF: 0.84   最大DD: 57.92R   平均保有: 16.3足
  スプレッド控除: 合計 33.35R（1トレード平均 0.070R）
  [range] 件数 282  勝率 44%  平均R -0.15  PF 0.75
  [trend] 件数 196  勝率 51%  平均R +0.04  PF 1.10
  決済理由: EOD=1 SL=261 TP=216
```

見出しの `実データ YYYY-MM-DD〜YYYY-MM-DD` は、実際に検証対象になったローソク足の期間（＝取得・読込後に `--start`/`--end` で絞った結果）です。**`--max-bars` は時足（H1 など）では上限に効きますが、日足（D1）ではほぼ効かない**（5万本 ≈ 約192年分）ため、D1 の「フル」はいつの間にか数十年分になっていることがあります。期間分割（`--start`/`--end`）を行う際は、まずこの表示で本当のデータ範囲を確認してください。

`[range]` / `[trend]` はエントリー時のレジーム（＝使用戦略）別の内訳です。どちらの戦略が稼いでいるか・負けているかが一目で分かります。

全トレードの詳細は `backtest_trades.csv` に保存されます。

### 実行（CSV から）

MT5 端末の履歴は同期済みの本数に依存します。**短い時間足（M1/M5）は数週間〜数ヶ月しか取得できないことが多い**一方、**日足（D1）などは数十年分（1971年〜）取得できることがあります**（実期間は見出しの `実データ YYYY-MM-DD〜YYYY-MM-DD` で確認）。取得したい期間が端末に無い場合は CSV 経由で長期検証できます。

1. MT5 で対象銘柄のチャートを開き、`ファイル` → `エクスポート`（または右クリック → 「保存」）で CSV を出力します。
2. `backtest_data/<銘柄名>.csv`（例: `backtest_data/EURUSD.csv`）に配置します。想定ヘッダは MT5 標準の `Date,Time,Open,High,Low,Close,TickVol,Vol,Spread` です。
3. 実行: `.\venv\Scripts\python.exe backtest.py --source csv --symbol EURUSD`

### 各種オプション

| オプション | 既定値 | 説明 |
|---|---|---|
| `--symbol` | （全銘柄） | 対象銘柄を 1 つに絞る |
| `--source` | `mt5` | `mt5`（端末から） / `csv`（`backtest_data/` から） |
| `--csv-dir` | `backtest_data` | CSV の配置先ディレクトリ |
| `--timeframe` | （config の値） | 時間足（M5/H1/H4 など）。MT5 取得専用の上書きで、config.json は変更しない |
| `--regime-timeframe` | （config の値） | 相場判定（ADX）に使う上位時間足（例 `M15`）。取引時間足と同じなら単一時間足。**上位足の取得は MT5 のみ対応**（CSV は単一時間足） |
| `--max-bars` | `50000` | MT5 から取得する最大本数 |
| `--spread` | （自動） | スプレッドを価格単位で固定。省略時は mt5 で銘柄の実スプレッド、csv で `config.spread_price` を使う |
| `--sweep` | （無効） | TP/SL 倍数を総当たりでバックテスト。単一戦略に固定して銘柄横断で集計する |
| `--sweep-strategy` | `trend` | スイープ対象の戦略（`trend`=EMAクロス / `range`=RSI逆張り） |
| `--sweep-tp` | `2.0,3.0,4.0,5.0` | スイープする TP（ATR 倍数）のカンマ区切りリスト |
| `--sweep-sl` | `2.0` | スイープする SL（ATR 倍数）のカンマ区切りリスト |
| `--box` | （無効） | ボックスレンジ逆張り戦略を単一戦略で検証（レジーム切替なし・指値約定） |
| `--box-sweep` | （無効） | ボックス戦略のパラメータ総当たり（`window` × `sl_buffer_atr`） |
| `--box-windows` | `10,20,30,40` | box-sweep するドンチャン窓（`window`）のカンマ区切りリスト |
| `--box-buffers` | `0.5,1.0,1.5,2.0` | box-sweep する SL バッファ（ATR 倍数）のカンマ区切りリスト |
| `--box-no-bb` | （無効） | box-sweep で BB 幅フィルタを無効にする（全 combo 共通） |
| `--start` | （全期間） | 開始日（`YYYY-MM-DD`）。この日以降のデータだけで検証（前後半に分けた再現性確認用） |
| `--end` | （全期間） | 終了日（`YYYY-MM-DD`）。この日以前のデータだけで検証 |
| `--out` | `backtest_trades.csv` | トレード履歴の出力先 |

### TP/SL スイープ（パラメータ総当たり）

「TP/SL をどの倍数にすれば期待値がプラスになるか」を、レジームを 1 つに固定して総当たりで測れます。
通常実行だと「トレンド戦略は 3R 狙い」「レンジ戦略は 2R 狙い」が混ざって集計されるため、
単一戦略（`force_regime`）に固定してその戦略の TP/SL だけを動かし、銘柄横断で合算します。

```powershell
# trend 戦略（EMAクロス）の TP を 2/3/4/5 倍、SL を 2/3 倍で総当たり（H1・実スプレッド込み）
.\venv\Scripts\python.exe backtest.py --timeframe H1 --sweep --sweep-strategy trend --sweep-tp 2.0,3.0,4.0,5.0 --sweep-sl 2.0,3.0

# range 戦略（RSI逆張り）も同様に
.\venv\Scripts\python.exe backtest.py --timeframe H1 --sweep --sweep-strategy range --sweep-tp 1.0,2.0,3.0 --sweep-sl 2.0
```

出力例:

```
=== sweep [trend]（H1 / 8銘柄合算 / 実データ 2018-06-01〜2026-10-10） ※実スプレッド込み ===
  TP=2.0 SL=2.0  件数  478  勝率  35.0%  平均R -0.041  PF 0.85  合計R  -19.6
  TP=3.0 SL=2.0  件数  478  勝率  34.2%  平均R -0.205  PF 0.72  合計R  -98.0
  TP=4.0 SL=2.0  件数  478  勝率  41.0%  平均R +0.048  PF 1.10  合計R  +22.9
      BTCUSD   件数   57  平均R +0.152  合計R   +8.7
      EURUSD   件数   61  平均R -0.031  合計R   -1.9
      ...
  ...
```

行は `TP` / `SL` の各組み合わせで、`勝率`（平均R がプラスになるか）と `PF`（1.0 超が合格ライン）に注目します。
「SL 距離の何倍まで利を伸ばせるか」を増やすほど勝率は下がりますが、損益分岐勝率も一緒に下がるため、
現在の勝率に対して TP が広すぎず狭すぎない点が最も有利になります。過学習に注意し、あくまで候補絞り込みの道具として使ってください。

**複数銘柄でスイープした場合**、各 (TP, SL) セルの下に**銘柄別の内訳**（平均R・合計R・件数、合計R 降順）が並びます。
「合算ではプラスでも、実は BTCUSD など 1 銘柄の単調ドリフトが稼いでいて、残りは負け」といった偏りが見えるため、
プラスが出たときは必ずこの内訳で「全銘柄に効くのか、特定銘柄の偏りなのか」を確認してください。単一銘柄（`--symbol`）指定時は内訳を出しません。

### ボックス戦略スイープ（パラメータ総当たり）

ボックス戦略（`--box`）は TP/SL を ATR 倍数で持たず、ドンチャン窓と SL バッファで価格構造が決まるため、
既存 `--sweep`（TP×SL）とは別に専用の `--box-sweep` を用意しています。**窓（`window`）と SL バッファ（`sl_buffer_atr`）**を総当たりし、BB 幅フィルタ・ADX 閾値など残りは config 値のままです。

```powershell
# window と SL バッファを総当たり（H1・実スプレッド込み）
.\venv\Scripts\python.exe backtest.py --box-sweep --timeframe H1 --symbol EURUSD

# スプレッドを 0 にして「グロス（控除前）の期待値」だけを見る（エッジ有無の確認）
.\venv\Scripts\python.exe backtest.py --box-sweep --timeframe H1 --symbol EURUSD --spread 0

# BB 幅フィルタを無効化して比較
.\venv\Scripts\python.exe backtest.py --box-sweep --timeframe H1 --symbol EURUSD --box-no-bb
```

出力例:

```
=== box-sweep [window × sl_buffer]（H1 / 1銘柄合算 / 実データ ... / ADX<25.0 / BB<0.05） === ※実スプレッド込み
  window=10 buffer=0.50  件数  120  勝率  30.0%  平均R -0.210  PF 0.60  合計R   -25.2
  window=20 buffer=1.00  件数   90  勝率  33.0%  平均R -0.150  PF 0.68  合計R   -13.5
  ...
```

読み方のポイント:

- **buffer を広げると `平均R` が（マイナスのまま）上方向へ動く**のは、ほぼ「スプレッドの R 換算が減る」だけです。真のエッジ有無は `--spread 0` で**グロスがプラスになるか**を見ます。
- グロスが全 combo で ±0 付近なら、それは「勝率が損益分岐勝率ちょうどに張り付く＝方向予測力ゼロ」のサインで、EMA/RSI と同じ結論です。パラメータ調整では勝ちに転じません。
- 期間分割（`--start`/`--end`）と併用して、プラスに見える combo が後半でも再現するかを必ず確認してください（過学習対策）。

### 成績の読み方

| 指標 | 見方 |
|---|---|
| 勝率 | 利益になったトレードの割合（単独では高ければ良いとは限らない） |
| 平均R | 1トレードあたりの期待値（**この値がプラスなら長期的に有利**） |
| PF（プロフィットファクター） | 総利益 ÷ 総損失。1未満は負け構造、1.5超が目安 |
| 最大DD | R 累計の過去最高からの最大下落（どこまで凹むか） |

### 前提・制約と注意

- エントリーはシグナル足の close、SL/TP は翌足以降の high/low で判定。同一足で SL/TP 両方到達した場合は保守的に SL を優先します（見通しバイアス＝未来データ参照を避けた設計）。
- **上位時間足レジーム**（`--regime-timeframe`）を使う場合、上位足の ADX は「取引足の確定時点で既に完成している上位足」までしか参照しません（形成中の上位足は使わない）。データは MT5 から取引足と上位足を別々に取得して時間対応付けします。
- **スプレッドは往復 1 スプレッド分を各トレードの R から控除**しています（買いは ask、売りは bid で約定する想定）。MT5 実行時は銘柄の実スプレッド、CSV 実行時は `config.spread_price`（または `--spread`）を使います。
- スリッページ・ローテーション選別・口座通貨換算の損益は織り込んでいません。
- **過学習に注意**: 過去データに合わせてパラメータを詰めすぎると未来で機能しません。結果は「過去にこうだった」という参考値として扱い、本番前に必ずデモ口座で実検証してください。
